## 〇、项目一句话

「闲物焕新」是一个 **社区旧物互换 + AI 智能体 + 积分生态** 平台：
居民把闲置物品发布到平台，可**免费送 / 等价交换 / 低价转让 / 交给平台回收**；
平台用大模型做**物品识别、智能定价、360° 展示、3D 重建、语音助老**；
赚取的积分可在「积分商城」兑换**社区商家**（打印店 / 便利店 / 理发 / 回收 / 家政）的服务，
再由商家核销、平台结算，形成资金与物品的双闭环。

三端结构：**用户端**（`agent_front`）+ **商家工作台**（`agent_front` 内 `/merchant/*`）+ **管理端**（`agent_admin_front`）。

> ⚠️ 名称澄清：后端的 `APP_NAME` 默认值是「社区旧物互换智能体平台」（`app/core/config.py:6`），
> 智能体对外名是「邻里通」（`AGENT_NAME`）；对外产品名「闲物焕新」在导航栏与首页硬编码
> （`agent_front/src/components/AppNav.vue:10`）。技术文档建议统一写「闲物焕新」，并在首次出现时注明。

### 3.1 技术创新

#### 创新点 1：**智能体助手「意图分流 + function-calling 工具调用」架构** ✅ 真实
**是什么**：一个智能体助手「邻里通」，把用户问题按意图分流到不同处理链路，每条链路都能调用真实工具查数据，再由 LLM 组织自然语言回答。

**怎么实现**（`app/services/agent.py:514` `stream_tokens`）：
```
物品/商家查询意图（关键词命中）  → 内部工具 search_items / find_nearby_items
                                  + 商家工具 get_merchant_list / get_merchant_products / get_points_balance
                                  + 高德 maps_geo（可串联：地名→坐标→找附近物品）
地图意图 + 高德MCP已配置        → 高德 MCP 全套工具（两轮：LLM决策→调MCP→结果回填→流式生成）
图表意图 + 图表MCP已配置        → generate_chart 工具 → 返回 markdown 图片
兜底                            → 普通流式对话
```
每条链路失败都自动降级到下一层，保证对话永不中断。

**比传统方式强在哪**：
1. **不让模型编数据**：System Prompt 硬约束「工具返回什么就说什么，工具返回空就如实说没有找到」（`agent.py:30`）；物品查询必须调工具，禁止「我无法查看附近物品」式敷衍。
2. **安全边界设计**：`get_points_balance` **不接收 user_id 参数**，由服务端注入 `viewer_user_id`——
   否则模型可能编造 id 去查他人积分（`merchant_tools.py:9`）。
3. **提示词与配置实时对齐**：积分规则不写死，每次请求从 `sys_config` 实时读取注入，
   避免管理端改配置后 AI 与平台说法矛盾（`agent.py:_read_effective_rules`、`assistant_prompts.build_points_rules_block`）。

#### 创新点 2：**位置/交接/需求三段式的匹配能力** ⚠️ 部分实现（请如实描述）
**实际包含三个独立能力，尚未合并成一个统一算法**：

1. **物品空间检索（Haversine 球面距离）** ✅
   - 实现：`app/services/item_query_service.py:23` `_haversine_km`；`find_nearby_items` 用
     **bounding box 粗筛 → Haversine 精算 → 按距离升序**（兼顾性能与精度）。
   - 隐私内建：仅返回 `user.location_public=1` 的物品，但**自己的物品始终可见**
     （`item_query_service.py:141`）——避免「关掉公开后自己反而看不到自己的东西」。
2. **交接可行性评估（行动能力 → 交接方式）** ✅
   - 实现：`app/services/match_service.py:15` `evaluate_handover`：
     行动能力 `limited/assisted` → 排除「自取」，只给「上门送达 / 志愿者代取」并推荐上门；
     正常用户 → 三种方式全给。
3. **需求侧匹配（期望物品 + 公开需求墙）** ✅
   - 实现：`item.expected_item`（想要的物品）+ `swap_demand` 表（`api/v1/demand.py`），
     首页需求墙把「邻居正在找什么」公开出来。

**必须如实说明**：上述三者在代码中是**独立模块**，**没有**一个统一的「三维相似度打分 + 排序」函数。
参赛文档应描述为「**位置维度（距离）+ 能力维度（交接方式）+ 需求维度（期望/需求墙）的多维匹配设计**」，
而不是「自研三维匹配算法」。若需要这个标题，建议先把三者串成一个排序服务再写。

#### 创新点 3：**3D 模型生成（图生 GLB）技术路线** ✅ 真实
**是什么**：物品详情页点「生成 3D 模型」，用物品已有照片生成可交互 3D 模型（GLB），
前端 Three.js 直接加载，形成 `3D 模型 → 360° 四视图 → 静态图` 的**三级降级链**。

**技术路线**（`app/services/three_d_service.py`）：
- **服务商可切换**：`MODEL_3D_PROVIDER=hunyuan|tripo`，默认腾讯混元 3D 极速版（`hy-3d-express`），
  Tripo 作为回退分支原样保留。
- **混元链路**：本地 JPEG → base64 提交 → 5s/300s 轮询（`queued/in_progress/completed/failed`）→
  取 `type=glb` 的 COS 签名 URL → **立即下载落盘**（签名 24h 失效）→ 回写 `item.model_status='ready'`。
- **工程防护**：
  - **GLB 魔数校验**（`b"glTF"`）：防接口静默返回 obj 文本、前端白屏（`_download_model:215`）；
  - **图片超 6MB 自动降质→缩边**（`_shrink_jpeg`）；
  - **失败原因落库**（`item.model_error`）+ 归一化成中文（并发/欠费/鉴权/风控/任务过期）；
  - **卡死兜底**：`generating` 超 5 分钟读时判失败，避免后端重启后前端永久转圈。

**与传统 360° 的区别**（这是很好的创新对比点）：
| 维度 | 360° 四视图（`panorama_service.py`） | 3D 模型（`three_d_service.py`） |
|---|---|---|
| 产出 | 前/左/后/右 4 张 JPG | 1 个 GLB 文件 |
| 技术 | 图像外推（Qwen-Image-Edit / wanx-imageedit） | 单图重建（混元 3D / Tripo） |
| 交互 | 伪 3D（深度视差） | **真 3D**（可任意旋转缩放） |
| 降级 | 单图 | 3D → 360° → 静态图 |

**真实运行数据**（2026-10-16 真机验证）：耗时 **97.2 秒**，GLB **12.16MB**，魔数 `glTF` 校验通过，前端 Three.js 成功渲染。

#### 创新点 4：**MCP（Model Context Protocol）工具集成** ✅ 真实
**是什么**：把外部能力（地图、图表）以 MCP 标准协议接入智能体，让 LLM 通过 function-calling 自主决策调用。

**集成了哪些工具**（`app/services/mcp_client.py`）：
- **高德地图 MCP**（streamable_http）：地理编码、周边搜索、距离、路线、天气等；
- **mcp-server-chart**（SSE）：生成饼图/柱状图/折线图，返回图片 URL。

**工程亮点**：
- **两种传输协议都支持**（SSE + streamable_http），适配不同 MCP 服务（`mcp_client.py:59`、`:227`）；
- **事件循环隔离**：MCP 客户端是异步的，而业务在 FastAPI 同步上下文里，
  因此用「独立线程 + 独立事件循环」执行（`_run_async`），避免 `asyncio.run()` 与主循环冲突；
- **工具清单缓存**：避免每次请求重连 MCP（`_amap_tools_cache`）；
- **工具 schema 自动转换**：MCP `inputSchema` → OpenAI function-calling schema（`_mcp_to_openai_tool`），
  并容忍不同 MCP 服务的参数命名差异（`call_chart_tool` 的参数名探测）。

#### 创新点 5：**Prompt 工程沉淀** ✅ 真实

#### 创新点 6：**AI 能力全链路降级设计** ✅ 真实（工程稳健性，很适合写）
- **模型级**：魔搭失败 → 自动降级百炼（`llm_client.image_edit/synthesize_speech/transcribe_audio`）；
- **能力级**：未配 Key → 演示模式；调用失败 → 词库/规则兜底
  （情感分析：LLM → 词典；助老意图：LLM → 关键词规则）；
- **展示级**：3D → 360° → 静态图；360° 外推失败 → 文生图补齐；
- **服务级**：每个 AI 调用都落 `ai_log`，管理端可监控。

### 3.2 模式创新

#### 创新点 7：**「平台中间商」回收模式** ✅ 真实
**是什么**：用户把物品「交给平台回收」，平台按成色估价**立即发积分**，物品进平台库存，
运营批量卖给合作回收商，平台赚差价。

**怎么实现**（`services/recycle_service.py`，状态机 `待取件→已入库→已售出`，可取消）：
- **估价是服务端唯一真源**：`estimate_points()` 纯函数，前端只调 `GET /recycle/estimate` 展示，
  **绝不接受前端传值**（否则可伪造 500 分）；
- **立即到账**（不用等成交），是与「寄卖/拍卖」最大的体验差异；
- **毛利可计算**：`recycle_stats` 给出「回收成本（积分折算）− 销售收入 = 毛利」。

**比传统二手平台强在哪**：传统平台只做撮合（C2C），用户要等成交；
本项目是「C2B + B2B」，**用户即时变现、平台赚流转差价**，把低价值闲置的流转效率拉满。

#### 创新点 8：**积分生态双闭环** ✅ 真实（核心商业模式）
**是什么**：存在两条互补的闭环。
- **物品闭环**：用户发布 → 审核通过 (+积分) → 邻居接手 → 双方完成 (+积分/碳减排)。
- **服务闭环**：用户积分 → 兑换商家服务 → 商家核销 → 平台按佣金结算给商家 → 商家获得社区客流。

**怎么实现**：
- 积分流水表 `points_log` 有**业务幂等唯一索引** `uk_points_log_source(source, related_id, user_id)`——
  同一笔业务绝不重复发分（`db/pool.py:291`）；
- 结算：`佣金 = 积分总额 × 汇率 × 佣金率%`，全程 Decimal（`merchant_service.calculate_commission`）；
- 兑换单过期自动退还积分（后台每小时扫描，单笔独立事务，`merchant_service.expire_redemptions`）。

**亮点**：这套设计让「善意交换」有了可持续的经济激励——用户赚积分、商家得客流、平台抽佣金，三方共赢。

#### 创新点 9：**「闲 / 新」双 Tab 设计** ✅ 真实
**是什么**：探索物品页用双 Tab 承载两种完全不同的供给：
- Tab「**闲**」（邻里二手）：物品交换/转让/赠送；
- Tab「**新**」（积分兑换）：用积分兑换商家服务/商品。

**怎么实现**（`agent_front/src/views/ItemList.vue:15`）：
- 「新」Tab **懒加载**（`lazy`），首次切换才挂载；
- **URL 是唯一真源**（`?tab=new`），前进/后退可同步；两个 Tab 状态互不干扰（切走不卸载）。

**比传统方式强在哪**：传统二手平台只有「物物」，
本项目把**「物 ↔ 积分 ↔ 服务」**三种价值形态放在同一个探索入口，用户逛一次能同时看到「换物」和「换服务」。

#### 创新点 10：**助老 / 无障碍模式** ✅ 真实
**是什么**：面向老年人与残障人士的三类适配模式：
- **助老模式**（`ElderlyMode.vue`）：大字号 + **语音交互闭环** + 三态大卡片；
- **视障模式**（`AccessibleMode.vue`）：高对比度 + 语音导航 + **物品语音标签**；
- **行动障碍模式**：跳过自取、推荐上门/志愿者代取。

**怎么实现**（后端 `services/elderly_service.py`、`accessibility_service.py`、`voice_service.py`）：
- **助老语音闭环**：语音识别（ASR）→ 意图理解（LLM，失败用关键词规则兜底）→ 执行操作 → 语音合成（TTS）回复；
- **结论三态化**：只输出「可以换 / 不行 / 已帮您联系」三种卡片，绝不给老人复杂选项；
- **语速控制**：助老模式语速 0.8、单句 ≤20 字（`voice_service.build_speech_text`）；
- **语音标签三级降级**：qwen-vl 多模态（看图判断颜色/成色）→ 纯文本生成 → 字段拼接；
- **紧急呼叫**：老人说「呼叫儿子」→ 推送到企业微信告警（`notify_service.push_help_alert`）。

**服务人群**：老年人、视障人士（`visually_impaired`）、行动障碍人士（`mobility_impaired`）。

### 3.4 工程质量创新（加分项，容易被评委认可）

- **数据一致性铁律**：跨表写入全部同一事务；积分发放靠**数据库唯一索引**做最后一道闸，

- **受控静态资源**：图片不再直链暴露，改为 HMAC 签名 URL，DB 只存相对路径（`core/security.py:52`）。
