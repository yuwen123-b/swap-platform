# 测试与部署环境说明（本地开发测试 / 云端部署）

> 取证时间：2026-10-22
> 取证方式：直接读取仓库配置与运行中的服务（`agent_back/.env`、`pyproject.toml`、`vite.config.js`、MySQL 实例、`uploads/` 目录、pytest 收集结果）。
> **重要前提**：仓库目前**没有任何云端部署产物**（无 `Dockerfile`、无 `docker-compose.yml`、无 `nginx.conf`、无 CI 工作流、无远程仓库）。因此下表中「云端部署环境」列是**与现有技术栈对齐的落地方案**，不是已上线现状；「本地开发测试环境」列则全部为实测值。

## 表 1　环境总览对比

| 维度 | 本地开发测试环境（现状，已实测） | 云端部署环境（规划，待落地） |
|---|---|---|
| 定位 | 功能开发、单元测试、端到端联调、演示录制 | 对外可访问的正式站点（用户 H5 + 管理后台） |
| 部署形态 | 单机：三个进程全部跑在同一台 Windows 机器 | 单台云服务器（2 核 4G 起）+ 云数据库 + 对象存储 |
| 操作系统 | Windows（开发机），命令行走 Git Bash | Linux，建议 Ubuntu 22.04 LTS |
| 后端运行时 | Python 3.12.10（`agent_back/.venv`），依赖由 `uv` 按 `pyproject.toml` + `uv.lock` 安装 | 同版本 Python 3.12，`uv sync --frozen` 保证依赖可复现 |
| 后端启动方式 | `python -m uvicorn app.main:app --port 8000`（**未带 `--reload`**，改代码须手动重启进程） | systemd 守护，`uvicorn --workers 4`（或 gunicorn + UvicornWorker），仅监听 `127.0.0.1:8000` |
| 后端监听端口 | `0.0.0.0:8000`（便于手机同局域网直连） | `127.0.0.1:8000`（只允许 Nginx 反代，不对外暴露） |
| 用户端前端 | Vite Dev Server `0.0.0.0:5173`，`/api` 代理到 `127.0.0.1:8000` | `npm run build` 生成 `dist/`，由 Nginx 托管静态文件，`/api` 反代后端 |
| 管理端前端 | Vite Dev Server `0.0.0.0:5174`，`/api` 代理到 `127.0.0.1:8000` | 独立子域（如 `admin.example.com`）托管 `dist/`；**不建议放子目录**（管理端 `vite.config.js` 未做 base 适配） |
| 前端构建基线 | `vite 6.0.5`；构建目标 `chrome87 / safari14 / ios14` | 同左，产物直接复用 |
| 数据库 | MySQL **8.0.37**，本机 `127.0.0.1:3306`，库名 `swap`，共 **34 张表** | 云 MySQL 8.0（保持同大版本），走内网地址，独立最小权限账号 |
| 数据库访问层 | `pymysql` + `dbutils` 连接池（min 1 / max cached 5 / max connections 20），**无 ORM** | 同左，按实例规格上调 `DB_POOL_MAX_CONNECTIONS` |
| 建表与迁移 | 后端启动时执行 `sql/*.sql` + 一组幂等 `ensure_*` 迁移，**自动补齐**表与列 | 同左（首次启动自动初始化）；正式环境建议改为上线前显式执行并留档 |
| 文件存储 | 本地磁盘 `agent_back/uploads/`（当前 **63 MB**），经 `/api/v1/static/*` 签名路由访问 | 对象存储（腾讯 COS / 阿里云 OSS）或云盘挂载；`uploads/` 已有 63 MB 存量需迁移 |
| 公网访问 | 仅一条 **ngrok 隧道** `https://silica-pushover-rudder.ngrok-free.dev`，写入 `PUBLIC_BASE_URL`，链路不稳定、重建即换域名 | 正式域名 + 备案 + HTTPS 证书（Let's Encrypt 或云厂商免费证书） |
| HTTPS | 无（手机通过局域网 IP 访问属非安全上下文，**麦克风被浏览器禁用**，只能测 UI） | **必须启用**：`getUserMedia`（录音）与自动播放策略都要求安全上下文 |
| 跨域策略 | `DEBUG=true` → 放行任意 `https?://*` | `DEBUG=false`，`CORS_ORIGINS` 只写正式域名，关闭通配 |
| 登录态 | JWT HS256；用户端 10080 分钟（7 天），管理端 1440 分钟（1 天） | 同左，但 `JWT_SECRET` 必须替换为 32 字节以上强随机值 |
| 静态资源鉴权 | HMAC-SHA256 签名 URL，有效期 3600 秒，密钥复用 `JWT_SECRET` | 同左；若改对象存储，需改用 COS/OSS 自带签名 |
| 外部 AI 服务 | 阿里云百炼 DashScope（对话 / 视觉 / ASR / TTS / 图像编辑）、腾讯混元 3D（TokenHub 网关）、魔搭 ModelScope（图像编辑、图表与地图 MCP）、高德 Web 服务、QQ 邮箱 SMTP、阿里云短信 | 同左；**全部为公网 HTTPS 调用，云上无需额外改动** |
| 3D 生成 | `MODEL_3D_ENABLED=true`（仅演示期开启，单次约 ¥1.8~3，并发上限 1） | 建议默认 `false`，按需开启，避免误触发产生费用 |
| 日志 | 代码内使用 `logging.getLogger`，但**未配置文件 handler**，实际只输出到进程 stdout | systemd journal + Nginx access/error log，按天切割并留存 30 天 |
| 进程守护 | 无，终端关闭即停；后台任务靠人工起 `run_in_background` | systemd `Restart=always`，开机自启 |
| 备份 | 无自动备份；数据仅在本地 MySQL | MySQL 每日全量 + binlog；`uploads/` 或对象存储跨区冗余 |
| 依赖管理 | `uv.lock`（后端）、`package-lock.json`（两端） | 同左，构建阶段用锁文件安装 |

## 表 3　关键配置差异（`agent_back/.env`）

| 配置项 | 本地当前值 | 云端建议值 | 差异原因 |
|---|---|---|---|
| `DEBUG` | `true` | `false` | 为 `true` 时 CORS 放行任意来源，且异常信息更详细 |
| `CORS_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173` | `https://example.com,https://admin.example.com` | 显式白名单，去掉通配 |
| `DB_HOST` / `DB_PORT` | `127.0.0.1` / `3306` | 云数据库内网地址 | 数据库与后端分离 |
| `DB_PASSWORD` | 本地开发口令 | 强随机、交由密钥管理 | 禁止弱口令与明文入库 |
| `JWT_SECRET` | 本地开发值 | 32 字节以上随机串 | **同时用于文件签名**，泄露等于图片直链全开 |
| `PUBLIC_BASE_URL` | ngrok 隧道地址 | `https://example.com` | 图像编辑需 DashScope 能回源下载图片 |
| `UPLOAD_DIR` | `uploads`（相对目录） | 对象存储挂载点或 `uploads` 绝对路径 | 云上需持久化，不能落在容器临时层 |
| `MODEL_3D_ENABLED` | `true` | `false`（演示时临时开） | 每次生成计费，云上易被误触发 |
| `MODEL_3D_PROVIDER` | `hunyuan` | `hunyuan`（`tripo` 为回退） | 混元走 base64 直传，不依赖公网回源 |
| `MERCHANT_ENABLED` | `true` | `true` | 商家闭环总开关，关闭后用户/商家侧接口全 403 |
| `EMAIL_PROVIDER` / `SMS_PROVIDER` | `smtp` / `aliyun` | 同左，Key 换生产账号 | 验证码通道 |
| `DASHSCOPE_API_KEY` 等 | 已配置 | 换独立生产 Key + 配额告警 | 本地与生产不共用额度 |
| `DB_POOL_MAX_CONNECTIONS` | `20` | 按实例规格上调（如 `50`） | 多 worker 时每进程各持一个池 |

> 安全项：`.env` 已被 `.gitignore` 忽略，仓库内只保留 `.env.example`（模板中密钥均为占位符）。云端严禁把真实 `.env` 提交或打进镜像。

## 表 5　云端上线缺口清单（按优先级）

| 优先级 | 缺口 | 说明 | 处理建议 |
|---|---|---|---|
| P0 | 无 `Dockerfile` / 部署脚本 | 无法一键构建与发布 | 后端写 `Dockerfile`（python:3.12-slim + uv），前端多阶段构建出 `dist` |
| P0 | 无 Nginx 配置 | 静态托管、`/api` 反代、SPA fallback、HTTPS 全缺 | 补 `nginx.conf`，`try_files` 兜底 history 路由 |
| P0 | 无 HTTPS | 录音、麦克风、部分媒体能力不可用 | 域名 + 证书，`:80` 强制跳 `:443` |
| P0 | 密钥与配置未分离 | 本地 `.env` 明文 | 改用环境变量注入 / 云密钥管理 |
| P1 | 文件存储在本机磁盘 | 63 MB 存量，扩容与备份困难；多实例无法共享 | 迁移对象存储，或至少挂独立云盘 + 定时快照 |
| P1 | 无进程守护与日志落盘 | 进程挂掉不自恢复，日志随终端消失 | systemd + journald / 日志轮转 |
| P1 | `/docs` 与调试信息外露 | 生产环境暴露接口清单 | 生产关闭 OpenAPI 或加白名单 |
| P2 | 无 CI | 测试与构建靠手工 | GitHub Actions：`pytest` + 两端 `npm run build` |
| P2 | 无自动备份 | 数据丢失不可恢复 | MySQL 每日全量 + binlog，保留 7~30 天 |
| P2 | 管理端不支持子目录部署 | `vite.config.js` 无 `base` 适配 | 优先用独立子域；如需子目录须补 `VITE_BASE` 与 router base |

## 附　启动命令速查

**本地（当前实际用法）**

```bash
# 后端（改代码后必须重启，未开 --reload）
cd agent_back
./.venv/Scripts/python.exe -m uvicorn app.main:app --port 8000

# 用户端
cd agent_front && npm run dev        # 0.0.0.0:5173

# 管理端
cd agent_admin_front && npm run dev  # 0.0.0.0:5174

# 测试与构建
cd agent_back && ./.venv/Scripts/python.exe -m pytest -q
cd agent_front && npm run build
cd agent_admin_front && npm run build
```

**云端（规划）**

```bash
# 依赖与启动
uv sync --frozen
uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 4

# 前端构建（在构建机执行，产物上传）
npm ci && npm run build     # 输出 dist/
# 子目录部署用户端时才需要：VITE_BASE=/h5/ npm run build
```
