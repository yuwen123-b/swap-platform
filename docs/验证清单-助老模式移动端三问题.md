# 验证清单 — 助老模式移动端三问题修复

日期：2026-10-20 ｜ 范围：`ElderlyMode.vue` / `VoiceInput.vue` / `utils/tts.js`（新增）+ 后端 TTS 音频链路
验证方式：CDP 无头 Chrome（390×844、移动端 UA、触摸仿真、假麦克风）41 项断言 + pytest 552 通过 + `npm run build` 通过

## 一、根因（比现象更深的两层）

| 现象 | 直接原因 | 真正根因 |
| --- | --- | --- |
| 长按弹「复制」菜单 | 浏览器默认选区 + 长按菜单 | 按钮只有 `user-select:none`，缺 `-webkit-touch-callout:none`，且 `touchstart` 未 `preventDefault` |
| TTS 时有时无 | 前端兜底 `speechSynthesis` 时灵时不灵 | **后端音频从来没播出来过**：① 静态路由白名单没有 `.mp3/.wav`，一律 403；② TTS 文件内容是 WAV 却写 `.mp3` 后缀，`nosniff` 下 MIME 与容器不符，iOS 直接拒解码；③ 返回的 URL **没有 HMAC 签名**，必然 403；④ 缓存里还有一个 5 字节的坏文件（内容 `"audio"`）永久命中 |

## 二、修改文件

**后端**
- `app/api/v1/files.py`：白名单新增 `.wav/.mp3/.m4a/.ogg`（仍强制签名 + nosniff）
- `app/services/voice_service.py`：新增 `audio_ext()` 按魔数判容器；落盘前校验字节，坏产物不缓存；历史「WAV 内容 + .mp3 后缀」命中时自动改名；URL 补 HMAC 签名
- `tests/test_voice_service.py`（重写 TTS 4 例 + 新增 4 例）、`tests/test_static_audio.py`（新增 5 例）、`tests/test_elderly_service.py`（1 处断言更新）
- 数据修复：`uploads/tts/` 坏文件删除、2 个错误后缀改名

**前端**
- `src/components/VoiceInput.vue`：操作区 `user-select:none + -webkit-touch-callout:none + touch-action:none`，`touchstart/touchend` 显式 `preventDefault`；触摸/指针双通道去重；录音态（加深 + 放大 + 呼吸灯 + 水波纹 + 秒数计时 + 「说完再松手，我在听」）；思考态（转圈 + 禁点）；「我听到您说」卡片；松手 <400ms 视为误触不发请求；滑出按钮取消；文字输入框保留可选中（回归不受影响）；修复输入行横向溢出（`min-width:0`）
- `src/views/ElderlyMode.vue`：`heard_text` 独立卡片；「正在思考，请稍等…」动效；「正在播报…/正在用手机朗读…」状态条；「再听一遍」按钮（用户手势内重播，天然绕过 iOS 自动播放限制）；离开页面停止播报
- `src/utils/tts.js`（新增）：复用单个 audio 元素 + 手势内静音解锁；`play()` Promise 必接（NotAllowedError → 降级）；后端音频 6s 未开播自动降级；speechSynthesis 逐句 onend 串行（规避 iOS 只念最后一句）；`window.__tts` 仅 DEV 暴露调试把手

## 五、真机验证指引（手机 + 电脑同一 Wi-Fi）

1. 电脑查局域网 IP：`ipconfig` → IPv4（如 `192.168.1.8`）
2. 前端以局域网启动：`npm run dev -- --host`，手机访问 `http://192.168.1.8:5173/elderly`
   ⚠️ HTTP + IP 属非安全上下文，**麦克风必被浏览器禁用**（页面会显示「为什么不能用麦克风？」，属预期）。
   要真机验证录音，须二选一：
   - **HTTPS 隧道**：`cloudflared tunnel --url http://127.0.0.1:5173`（或 ngrok），用返回的 `https://` 地址访问；
   - **Android Chrome 远程调试**：手机 `chrome://inspect`，配合「不安全来源视为安全」标志。
3. 真机重点看四件事（无头环境模拟不了）：
   - 长按按钮 1~2 秒：iOS/微信不应弹出「拷贝/全选」菜单
   - 按住时的颜色加深、放大、水波纹，松手后「正在思考…」
   - 回答出来后：先「正在播报…」，随后能听到声音；若无声，点「再听一遍」（该按钮在用户手势内播放，必定生效）
   - iOS Safari / 微信内置浏览器各验一遍（自动播放策略差异最大的两端）
4. 验证后端音频是否真的出声：真机连电脑后用 `chrome://inspect` 查看 Console，`window.__tts.state.mode` 为 `server` 即后端音频，`browser` 即本地兜底

## 六、遗留与建议

- `AccessibleMode.vue` 仍用裸 `speechSynthesis`（点击触发、有手势上下文，风险低），可后续统一改走 `utils/tts.js`
- 「再听一遍」目前每轮回答后出现一次；如需「常驻重听」，把 `lastSpeech` 持久化到 sessionStorage 即可
- 后端 TTS 每次合成约 1~2s，弱网下前端 6s 兜底已覆盖；若想更快，可对常见回复做预热
