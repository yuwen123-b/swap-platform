## 4. 实现层的 3 个决定（与任务书的差异）

1. **预览接口按「当期」而非「全部已核销未结算」**：`settle_merchant` 的真实口径是 当月 + `redeemed_at` 落区间 + status=2，预览必须同口径，否则确认框承诺的数字仍是错的（跨月场景下偏大）。`period` 缺省当月。
2. **本期无核销单的商家，[结算] 按钮禁用**（tooltip「本期没有需要结算的核销单」）：`settle_merchant` 对 0 单也会写一行结算记录，禁用可避免产生垃圾行。
3. **「订单管理」菜单改名「物品交换订单」**：按你确认的 5 处落差处理 #5；路由 meta.title 同步改（浏览器标签页标题一致）。

## 5. 已知边界（非缺陷）

- **待审核置顶是"当前页内"排序**：后端 `/merchant/list` 按 `id DESC` 返回，前端在页内把待审核排前。数据量大、待审核落在第 2 页时，需用「待审核」Tab（走后端 `status=0` 参数）定位——这也是 Tab 存在的意义。
- **截图 11（role=3 结算页）里商家 1 显示「本期已结算」**：那是验证过程中的瞬时状态（脚本结算后截的图），收尾已还原。你手工验收时会看到全部「待结算」。
- 数据已还原：`merchant 13 → status=0`、`merchant_settlement` 清空。**你手工验收时可以重新走一遍「通过 + 结算」全流程。**
