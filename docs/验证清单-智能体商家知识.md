## 八、实现要点（供后续维护）

| 要点 | 说明 |
|---|---|
| **提示词分层、追加不改写** | `BASE_SYSTEM_PROMPT = SYSTEM_PROMPT(原文) + PLATFORM_OVERVIEW + 实时规则块 + SCOPE_NOTICE [+ 英文指令]`；`SYSTEM_PROMPT` 逐字未改 |
| **范围协调句** | `SCOPE_NOTICE` 必须收尾，划清「仅用户主动询问时才讲平台规则」，否则与原文「不主动推荐操作」约束打架，模型会拒答或到处挂建议 |
| **工具并入而非新开分支** | 新开商家分支要决定插在物品分支前/后，「附近有没有打印店」（含物品关键词）与「兑换一本教材」（含商家关键词）会互相抢单；并入后由 LLM 自选，误判只多一次调用不会答错 |
| **`user_id` 服务端注入** | 3 个工具 schema 的 properties 均不含 `user_id`；`get_points_balance` 只认 `viewer_user_id`，防模型编造 id 查他人积分（已有测试锁死） |
| **积分数字实时读 `sys_config`** | DB 现值 10 / 20 / 5.0，代码兜底 20 / 50；写死会与配置漂移。每次请求 1 次小 SELECT，失败回落默认值 |
| **工具只读 + 不抛异常** | 失败一律返回 `{"error": ...}` 交给 LLM 措辞，避免一个工具抖动中断整轮对话 |
| **`[TOOL_CALL]` 只记一次** | `agent._call_item_tool` 打 INFO，`merchant_tools` 降为 debug —— 否则日志出现两行重复，干扰「工具是否真被调用」的排查 |

## 九、已知边界（非缺陷）

1. **关键词「兑换」会把部分物品问题拉进工具分支**：安全——该分支工具集含 `search_items`，且实测「兑换一本教材」类问题不会答错。
2. **流程类问题不调工具**：问「怎么兑换」时模型按提示词直接回答（实测 9.7s，无工具往返），这是指令里明确要求的，避免每次都在流程问题上多一次非流式往返。
3. **`elderly_prompts.py` 的 `ELDERLY_SYSTEM_PROMPT` 当前无引用**（助老链路只用了 `ELDERLY_INTENT_PROMPT`），属既有状态，本次未动。
4. **英文模式（`lang='en'`）当前无调用方**：`ai.py:69` 固定传 `"zh"`。本次仍把 `EN_LANGUAGE_DIRECTIVE` 调整到提示词末尾，保证将来启用时语言指令不被中文平台知识覆盖。
