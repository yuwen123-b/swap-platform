# 排查报告 — 物品详情页「生成 3D 模型」按钮无反应

- 时间：2026-10-16 12:39 – 13:05
- 现象：物品详情页点「生成 3D 模型」没有反应（无报错、无状态变化、无模型产物）
- 结论：**按钮和链路本身都是好的**，根因是**百炼账号的 Tripo 服务处于未激活状态**（两种模型都报同一个错）；
  但「失败」在产品里**完全不可见**，用户感知就是"点了没反应"——这半个缺陷已用代码修掉。
- 修复：后端落库并透出失败原因 + 前端三处可见性修复（pytest **512 passed** / build ✅ / CDP **18/18**）

## 三、根因证据（真实调用，非猜测）

复现脚本：`.workbuddy/_probe_3d/repro.py`（提交 + 轮询，打印原始响应）

```
[3] 提交响应 HTTP 200  →  task_id = fd29b555-…
[5] 轮询：#1 (+2.6s) RUNNING → #2 (+13.1s) FAILED
[6] {"task_status":"FAILED",
     "code":"InvalidParameter",
     "message":"The product is not activated, please confirm that you have
                activated products and try again after activation."}
```

**差分实验**（`.workbuddy/_probe_3d/diff_check.py`，故意给一个抓不到图的 URL 让任务必然失败，从而不计费）：

| 被测模型 | 终态 | message |
|---|---|---|
| `Tripo/Tripo-H3.1` | FAILED | The product is **not activated** |
| `Tripo/Tripo-P1.0` | FAILED | The product is **not activated** |
| 同一把 Key → `qwen-turbo` | HTTP 429（限流，**鉴权通过**） | — |
| 同一把 Key → 3D 提交 | HTTP 200（能拿 task_id） | — |

**判定链**：Key 有效（qwen 能鉴权）→ 3D 提交也被受理 → 只有**任务终态**报未激活 → **百炼侧 Tripo 产品未激活/失效**，与代码、Key、网络、ngrok 隧道均无关。

> 对照 10-14 的探针史（`docs/探针报告-Tripo3D生成.md`）：当时连报三轮 `not activated`，用户开通后约 10 分钟生效即 SUCCEEDED。今天同样的错误**两种模型都复现**，说明 Tripo 的激活状态又不可用了（或免费额度/试用到期），需在百炼控制台确认。

**已排除的嫌疑**（实测通过，不用再查）：
- ngrok 隧道：`https://silica-pushover-rudder.ngrok-free.dev/api/v1/static/...?exp=&sig=` → **200 image/jpeg 62974 bytes**，Tripo 抓得到图
- 签名静态路由：本地 400 是"未签名"的预期行为，带签名 200
- 提交参数：与官方示例逐字一致（`model/input.image/parameters.texture_quality`，未发 H3.1 专属的 `geometry_quality`）
- `MODEL_3D_ENABLED`、PUBLIC_BASE_URL、API Key：全部就位

## 四、修掉的三个真实缺陷（"无反应"的产品层根因）

| # | 缺陷 | 修复 |
|---|---|---|
| **D1** | **失败原因没有任何出口**：后端只 `logger.warning`（终端无落盘日志），库里不存，接口不下发；前端把状态悄悄改回 failed、按钮变回「重新生成」，零提示 → 用户"白点了一下" | `item` 新增 `model_error VARCHAR(500)`（幂等迁移）；`run_generate` 失败原因落库（截断 500）；`GET /model/{id}` 与 `GET /items/{id}` **仅 failed 时**透出；前端按钮下方直接展示（长文本两行截断，原文在 `title`） |
| **D2** | **点击后画面零变化**：物品已有 360° 时，降级链 `panoReady` 优先于「生成中」角标，点击后唯一的可见反馈是一个几秒后消失的 toast | 新增**独立浮层** `.model-generating-tip`（右上角、绿色胶囊、旋转 spinner），`model_status==='generating'` 时无论当前渲染哪个查看器都可见；`pointer-events:none` 不挡 360° 拖拽 |
| **D3** | **轮询窗口错位 + 状态卡死**：前端 80×3s=240s < 后端 300s 卡死兜底；耗尽后本地状态永远停在 generating → 按钮再也回不来，只剩刷新一条路 | 上限 80→**120**（360s，长于后端 300s）；耗尽时**再同步一次真实状态**再决定提示，不再把本地状态永久留在 generating |
| 附加 | 「生成中→失败」的转变完全静默 | `pollModel` 检测到该转变时主动 `ElMessage.error`（6s），并按已知上游错误给出**可执行的中文提示**（如 `not activated` → "百炼 Tripo 服务未开通或未生效，请在阿里云百炼控制台确认开通状态后重试"） |
