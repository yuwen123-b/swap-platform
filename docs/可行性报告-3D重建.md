## 三、Tripo API 规格（已拿到全文，实现可直接照抄）

| 项 | 值 |
|---|---|
| 创建任务 | `POST https://dashscope.aliyuncs.com/api/v1/services/aigc/video-generation/3d-generation`（北京地域；新域名 `{WorkspaceId}.cn-beijing.maas.aliyuncs.com` 同路径） |
| 必带请求头 | `Content-Type: application/json`、`Authorization: Bearer sk-xxx`、**`X-DashScope-Async: enable`**（缺失会报 "does not support synchronous calls"） |
| 模型 | `Tripo/Tripo-H3.1`（高精度，最高 200 万面，较慢）｜`Tripo/Tripo-P1.0`（最高 2 万面，更快） |
| 输入三选一（互斥） | `input.prompt` 文生3D｜`input.image` 单图生3D｜`input.images[]` **多图生3D** |
| **多图数组规格** | 长度固定 4，**顺序为「前、左、后、右」**，不需要的视角传 `{}`（有效图 2~4 张）；元素 `{type: "png"\|"jpeg", file_token: "<公网URL>"}` |
| 图片要求 | JPEG/PNG，边长 [20,6000]（建议 >256），≤20MB，**必须是公网 HTTP(S) URL** |
| 参数 | `texture_quality`: standard(默认)/detailed；`geometry_quality`: standard/ultra（仅 H3.1）；`pbr` 默认 true；`texture` 默认 true |
| 轮询 | `GET /api/v1/tasks/{task_id}`，状态 `PENDING→RUNNING→SUCCEEDED/FAILED/CANCELED/UNKNOWN`；**建议间隔 15s**；task_id 有效 24h；查询接口 RPS 20 |
| 结果字段 | `output.results[0].pbr_model_url`（**GLB，2 小时有效**）、`base_model_url`（`texture=pbr=false` 时）、`rendered_image_url`（预览渲染图，2h）、`usage.3d_task_type` |
| 生成耗时 | 文档口径「约需数分钟」；调度器实测（本轮）从提交到失败仅 2.4s（因未开通，无法取得真实耗时） |

### ⚠️ 关键发现（方案 A 的加分项 + 拦路虎）

- **加分项**：多图生3D 的图片顺序恰好是**前、左、后、右 —— 与现有 panorama 四视角产物完全对齐**。
  因此正确顺序是先修视角一致性（上一批已定：换 `qwen-image-2.0-pro`），再做**多图生3D**，
  质量会明显优于单图；多图与单图**同价**。
- **拦路虎**：`image` / `file_token` **只支持公网 URL，文档未提供 base64 方案**。
  我们的视角图存在本地 `uploads/`，签名 URL 是 `127.0.0.1` 的，Tripo 拉不到。
  → 必须配置 `PUBLIC_BASE_URL` 指向公网可达地址（本地开发可用 ngrok / cloudflared 隧道，
  `.env` 注释里原本就为「图像编辑」预留了 ngrok 思路），或把服务部署到公网。

## 四、成本估算

| 场景 | 单价 | 每物品 |
|---|---|---|
| 单图生3D H3.1（标准版+标清贴图） | 2.1 元/次 | 2.1 元 |
| 多图生3D H3.1（标准版+标清贴图） | 2.1 元/次 | 2.1 元 |
| 单图/多图生3D P1.0（带标清贴图） | 3.5 元/次 | 3.5 元 |
| 无贴图最省（H3.1 标准+无贴图） | 1.4 元/次 | 1.4 元 |
| + 视角一致性修复（3 张 qwen-image-edit） | 0.3 元/张 | +0.9 元 |
| **合计（多图生3D H3.1 带贴图 + 视角修复）** | — | **≈ 3.0 元/物品** |

**成本护栏建议**：改为**手动触发**（用户点「生成 3D」，不走发布自动），并加
`MODEL_3D_ENABLED` 配置开关（默认关，演示时开）。否则每个物品白烧 2~3 元。
限流：RPM 5，足够（单机场景）。

若走本地 GPU（方案 B 的替代）：需 ≥6GB 显存的 NVIDIA 卡（如 RTX 3060 12G，约 2000 元，或云 GPU 按小时租），
外加 torch + TripoSR/Hunyuan3D 权重（≥10GB 磁盘），且质量（TripoSR）明显低于 Tripo API（贴图烘焙、低模）。
**结论：本机不可行，且性价比不划算。**

## 五、方案对比与推荐

| 方案 | 前置条件 | 预期效果 | 耗时 | 结论 |
|---|---|---|---|---|
| **A. 百炼 Tripo 3D** | ① 控制台开通 Tripo；② 公网图片 URL（隧道/部署） | 真 3D 网格（GLB），支持 PBR 贴图 + 多图生3D | 视角 60s + 3D 数分钟 | ✅ **推荐** |

| C. 砍掉 3D | 无 | 保留现有 4 图 360°，隐藏入口 | 0 | 备选 |

2. **打通链路**：配 `PUBLIC_BASE_URL` 隧道 → 我用公开样例图 + 你的物品图各跑一次真实 3D 生成，
   把 GLB 与 `rendered_image_url` 预览图给你人工看效果；

## 六、实现要点（确认后执行时注意）

1. **数据库**：item 表**无** `model_url` / `model_status` 列 → 走现有 `_ensure_column` 幂等补列
   （与 `panorama_views/status/generated_at` 三列同款写法），零迁移脚本。
2. **异步**：GLB 链接 **2 小时失效** → 必须在任务成功后**立即下载**存本地
   `uploads/items/{id}/models/model.glb`（现有 `download_file` 可复用）。
3. **超时**：3D 生成「数分钟」，现有 panorama 的 10 分钟卡死兜底可复用思路，
   但需给 model 单独的状态与超时（建议 15 分钟）。
4. **前端渲染**：GLB 带 PBR 材质，**必须加灯光/环境光**（现有查看器是无光照的
   `MeshBasicMaterial`，直接套用会发黑）。新建独立 `ModelViewer.vue`
   （`MeshStandardMaterial` + `AmbientLight`/`DirectionalLight` + `OrbitControls` 式拖拽 + 滚轮缩放 + 自动旋转），
   **不碰 `PanoramaViewer.vue`**，360° 的拖拽/切换原图/俯仰/助老模式全部不受影响。
5. **降级链**：`model_status != ready` 或 GLB 加载失败 → 显示现有 4 图 360°；4 图也失败 → 静态图。
6. **零新依赖**：后端只用 `requests`（现成）；前端 GLTFLoader 来自已装的 three。
