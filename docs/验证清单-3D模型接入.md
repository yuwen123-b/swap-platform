### 关键实现取舍
1. **只发送 `texture_quality`**：官方文档明确 `geometry_quality` **仅 Tripo-H3.1 支持**，对 P1.0 传它会被判 `InvalidParameter`。因此代码里硬性不发该字段（有单测断言）。
2. **开关后端硬校验**：`three_d_service.is_enabled()` 在 `POST /model/generate` 与 `generate_3d_model()` 各判一次；关闭时返回 403。前端只是跟着隐藏按钮，绕过前端也拿不到能力（防白烧 2~3.5 元/次）。
3. **`is_enabled()` 由 item.py 调用而非读 `item_api.settings`**：开关语义属于 3D 服务，`GET /items/{id}` 直接问服务要，避免 item 模块反向承担业务判断。
4. **`model_url` 存静态地址不存签名**：签名 1 小时有效，落库会立刻过期；统一「读取时现场签名」，与 `panorama_views` 完全同口径。
5. **超时兜底 5 分钟**（按决策）：读时判定，后台线程随重启丢失时前端不会永久转圈。
6. **GLB 先写 `.part` 再 `replace`**：避免半截文件被前端当成品加载。
7. **上传原图本地化为 `uploads/items/{id}/models/source.jpg`**：Tripo 只吃 JPEG/PNG 且只接受公网 URL（不支持 base64），WEBP（如 item 73）必须先转码。

## 七、手动验收步骤（需真实调用，会花钱 2~3.5 元/次）

前置：`agent_back/.env` 置 `MODEL_3D_ENABLED=true` 并重启后端；`PUBLIC_BASE_URL` 指向可用的公网隧道（ngrok）。

1. 打开自己的物品详情页 → 左下角出现「生成 3D 模型」按钮（非所有者 / 开关关闭时**不出现**）
2. 点击 → 提示「3D 模型开始生成，约 2-4 分钟」，画面切为原图 + 角标「3D 模型生成中」
3. 2-4 分钟后自动切换为 3D 模型（**光照正常，不发黑**）
4. 拖拽旋转 / 滚轮缩放 / 双击回正 / 自动旋转开关均生效
5. 失败路径：把 `PUBLIC_BASE_URL` 清空后触发 → 约 5 分钟后状态转 `failed`，画面**自动回落到 360° 四视图**（未生成则静态图），不出现空白

## 八、待你确认的两点

1. **`P1.0` 未经真实调用验证**：探针成功的是 `H3.1`（144 万面 / 40.8 MB），按你的决策默认改为 `P1.0`（≤2 万面、文件小）。参数形状已按官方文档对齐（不发 `geometry_quality`），但**首次真实生成建议人工确认一次产物效果与耗时**。若效果不够好，改 `.env` 的 `MODEL_3D_MODEL=Tripo/Tripo-H3.1` 即可，代码无需改动。
2. **超时兜底与后台实际耗时的边界**：读侧 5 分钟判 `failed`（按你的决策），而后台轮询上限也是 5 分钟 + 下载最多 5 分钟。若 Tripo 排队特别久，可能出现「前端显示失败、稍后刷新变成 ready」的情况（单调向好，不产生脏数据）。
