## 三、落地方案设计

### 3.1 数据模型（3 列，非 2 列）

```sql
ALTER TABLE item ADD COLUMN model_url        VARCHAR(500) NULL COMMENT '3D 模型相对路径（读取时签名）';
ALTER TABLE item ADD COLUMN model_status     VARCHAR(16) NOT NULL DEFAULT 'none' COMMENT 'none/generating/ready/failed';
ALTER TABLE item ADD COLUMN model_generated_at DATETIME NULL COMMENT '生成起始/完成时间（卡死兜底）';
```

> **为什么多一列 `model_generated_at`**：`panorama` 靠 `panorama_generated_at` 做「`generating` 超时兜底」，
> 否则后端重启导致任务丢失时，前端会**永久轮询「生成中」**。3D 生成 2.5 分钟 + 40MB 下载 46s，
> 这个兜底比 panorama 更必要。不加这一列就只能复用 `updated_at`（会被其它更新污染，不可靠）。

### 3.2 后端

**新增 `app/services/three_d_service.py`**（命名 `3d_service` 是非法标识符，用 `three_d_service`）

```
generate(item_id) -> dict          # 同步执行：取图→转码→签名URL→提交→轮询→立即下载 GLB→落库
run_generate(item_id) -> None      # BackgroundTasks 入口：置 generating，异常置 failed，绝不抛出
get_status(item_id) -> dict        # 查询状态 + 签名后的 model_url + 卡死兜底
```

关键实现点（全部来自探针实测）：
- 端点 `POST https://dashscope.aliyuncs.com/api/v1/services/aigc/video-generation/3d-generation`，查询 `GET /api/v1/tasks/{task_id}`
- `model = Tripo/Tripo-H3.1`（可配），`X-DashScope-Async: enable`，`parameters={texture_quality:standard, geometry_quality:standard}`
- **轮询上限 5 分钟**（实测 145s），间隔 15s
- **`SUCCEEDED` 后必须立即下载**（链接 2 小时失效；实测 40.8MB 耗时 46.4s）
- 落盘 `uploads/items/{item_id}/models/model.glb`；DB 存相对路径 `/api/v1/static/items/{id}/models/model.glb`
- 失败一律置 `failed` + 记录日志，**不做任何重画降级**（用户既定原则：宁可失败，不要乱画）

**新增 `app/api/v1/model3d.py`**（挂载为 `/api/v1/model`）

| 接口 | 行为 |
|---|---|
| `POST /model/generate` | 所有者校验 + `generating` 重复触发保护 + `MODEL_3D_ENABLED` 硬校验 → `BackgroundTasks` → 返回 `{status:'generating'}` |
| `GET /model/{item_id}` | 返回 `{status, model_url, generated_at}`，`model_url` **读取时现场签名**；公开可读 |

### 3.3 前端

**新增 `src/components/ModelViewer.vue`**
- `GLTFLoader`（可选挂 `DRACOLoader` 解码器，为后续压缩预留）加载 GLB
- **光照**：`RoomEnvironment` + `PMREMGenerator`（首选，PBR 质感真实）或 `AmbientLight` + `DirectionalLight` 组合
- `OrbitControls`：拖拽旋转 / 滚轮缩放 / 自动旋转；限制 `minDistance`/`maxDistance`
- 加载进度：`onProgress` → 进度条（40MB 首次加载慢，必须有）
- props：`modelUrl`；emit：`error`（加载失败交由父组件降级）
- 无障碍：`aria-label` + 键盘可旋转，样式承接 `html.mode-elderly` / `html.theme-high-contrast`

**新增 `src/api/model.js`**：`triggerModel3D(itemId)` / `getModel3D(itemId)`

**`ItemDetail.vue` 改动**（视觉区优先级降级链）

```
① model_status==='ready' 且未失败   → <ModelViewer />
② panorama_status==='ready'        → <PanoramaViewer />      ← 现有逻辑不动
③ model_status==='generating'      → 原图 + 「3D 模型生成中，约 2-3 分钟」
④ panorama_status==='generating'   → 原图 + 「360° 生成中」   ← 现有逻辑不动
⑤ 否则                              → 静态图
```
- 新增按钮「生成 3D 模型」（仅 `isOwner` + `MODEL_3D_ENABLED` 开启 + `model_status ∈ {none,failed}` 时显示）
- 新增轮询：间隔 5s，上限 60 次（5 分钟），与现有 pano 轮询相互独立
- `onModelError` 重试一次（刷新签名）后降级到 ②

### 3.4 开关

- 后端 `settings.model_3d_enabled: bool = False`（`.env` 的 `MODEL_3D_ENABLED`）
- **后端硬校验**：`false` 时 `POST /model/generate` 直接 400/403（防止绕过前端白烧钱）
- 前端展示：在 `GET /items/{id}` 返回体**新增 `model_3d_enabled` 布尔字段** → ItemDetail 零额外请求即可决定按钮是否显示

## 四、⚠️ 与任务书的 3 处偏差（必须调整）

### 偏差 1【致命】`files.py` 的 MIME 白名单没有 `.glb`，不改直接 403

任务书要求 `model_url: '/uploads/items/{id}/models/model.glb'`。但本项目 uploads 目录**早已不再静态挂载**
（第 7 批安全改造：改为 HMAC 签名路由 `app/api/v1/files.py`），且该路由的 `_EXT_CONTENT_TYPES`
白名单只有图片格式 —— **`.glb` 请求会 403「不支持的文件类型」，模型永远加载不出来**。

**必须做**：给白名单加 `.glb → model/gltf-binary`（顺带 `.gltf → model/gltf+json`）。
**URL 形态**：改用签名 URL `/api/v1/static/items/{id}/models/model.glb?exp=&sig=`，DB 只存相对路径、读取时签名（与 `panorama_views` 完全一致）。

**已实测坐实**（用探针产出的真实 GLB 走真实静态路由）：

```
_probe3d/model_pbr.glb -> HTTP 403 | {"code":403,"message":"不支持的文件类型"}
_probe3d/preview.png   -> HTTP 200 | image/png | 137754 bytes   ← 对照组正常
```

### 偏差 2【致命】Tripo 只接受 JPEG/PNG，而物品图可能是 WEBP

实测：`item 73` 的本地原图是 **WEBP**；外链 unsplash 图带 `auto=format` 也可能返回 WEBP。
直接送 WEBP 给 Tripo 会失败。

**必须做**：送 Tripo 前统一「本地化 + 转 JPEG」（600×600~1080×1080，质量 92），再生成签名 URL。
**且**：Tripo **只吃公网 URL**（不支持 base64），依赖 `PUBLIC_BASE_URL` 已配（现已配好）；若为空则直接判 `failed`。

### 偏差 3【建议】增列 `model_generated_at`

理由见 3.1。不加则「后端重启后前端永久转圈」这一故障无法自愈。

## 六、风险矩阵

| 风险 | 等级 | 缓解 |
|---|---|---|
| 40.8MB GLB 首次加载数十秒 | **高** | ① 加载进度条；② 建议先对比 `Tripo-P1.0`（2 万面，文件小得多）；③ 后续可选 Draco 压缩（Three.js 自带解码器） |
| 后端重启导致状态悬挂在 `generating` | 中 | `model_generated_at` + 超时兜底（同 panorama 的 10 分钟思路） |
| 每次生成烧 2.1 元 | 中 | `MODEL_3D_ENABLED` 默认关 + 仅所有者可见 + 重复触发保护 |
| `BackgroundTasks` 被长期占用 | 中 | 3D 任务约 3.5 分钟（生成 2.5 + 下载 0.8）。同步 `def` 会走线程池，不阻塞事件循环；但并发多物品时线程池会紧张，需限制并发（沿用 `generating` 保护） |
| 签名 URL 1 小时过期 → GLB 404 | 中 | ModelViewer 失败 → 父组件刷新详情换签名重试一次 → 再失败降级 360° |
| 一次请求最多传 40MB（经 vite proxy） | 中 | 演示前先跑一次预热；或换 P1.0 |
