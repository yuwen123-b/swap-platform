# 排查报告：助老模式「语音识别暂不可用」

> 记录时间：2026-10-20 21:30–21:50
> 现象：助老模式按住说话后，接口返回 503，前端提示「语音识别暂不可用，请改用文字输入」。

## 一、结论

**配置的两级语音识别链路都是断的，与前端录音、麦克风、权限无关。**

| 链路 | 配置值 | 实测结果 | 判定 |
|---|---|---|---|
| 主：魔搭 ModelScope | `ASR_PROVIDER=modelscope`，`FunAudioLLM/Fun-ASR-Nano-2512` | `POST /v1/audio/transcriptions` → **HTTP 404 page not found** | ❌ 该网关没有音频端点 |
| 兜底：百炼 paraformer | `LLM_ASR_MODEL=paraformer-realtime-v2` 走 `/services/audio/asr/transcription` | 提交成功但任务**秒级 FAILED**，`code=SERVER_ERROR`，`results=[]` | ❌ 模型不适用/未开通 |
| 兜底所需的公网 URL | `PUBLIC_BASE_URL=https://silica-pushover-rudder.ngrok-free.dev` | 根路径与音频路径均返回 **ngrok 官方 404 页** | ❌ 隧道已失效 |

**最终可用的是第三条路：`qwen3-asr-flash`（多模态接口 + base64 直传）**，实测完全正常，且不需要公网 URL。

## 二、证据

### 2.1 魔搭网关没有音频能力

```bash
# 模型列表可达，但共 37 个全部是文本模型，无任何 audio/ASR/TTS 条目
curl -s https://api-inference.modelscope.cn/v1/models -H "Authorization: Bearer $MS_KEY"  → HTTP 200
# 三个音频端点全 404
/v1/audio/speech          → 404
/v1/audio/transcriptions  → 404
/v1/audios/transcriptions → 404
```

同理，`TTS_PROVIDER=modelscope` 也一直在 404 后静默降级到百炼——所以虽然合成能用，但每句话都白撞一次 404。

### 2.2 paraformer 文件转写在本账号不可用

用 TTS 合成一段**内容已知**的 WAV（"我想换电饭煲"）排除音频格式因素，结果同样是：

```
task_status: FAILED   code: SERVER_ERROR   results: []   subtask_status: FAILED
```

秒级失败、无错误详情，与「模型未开通」的表现一致（此前 Tripo 3D 也是同类问题）。

补充：原配置 `LLM_ASR_MODEL=paraformer-realtime-v2` 本身也是错的——它是**实时流式**模型，录音文件转写接口不接受；文件转写应用 `paraformer-v2`。

### 2.3 音频真实格式与文件名不一致

真机两条录音（`uploads/voice/*.webm`）文件头为 `00 00 00 20 66 74 79 70`（`ftyp`）——**实际是 MP4/AAC**，因为 Chrome 新版 `MediaRecorder` 产出 `audio/mp4`，而前端把文件名硬编码成 `recording.webm`。若按扩展名判断格式会喂错容器。

### 2.4 qwen3-asr-flash 实测结果

| 输入 | 输出 | 耗时 |
|---|---|---|
| TTS 合成 WAV（内容：我想换电饭煲） | `我想换电饭煲。` | 1~2s |
| 真机录音 fd5b9cce（MP4/AAC） | `喂喂喂。` | 1~2s |
| 真机录音 cda3d739（MP4/AAC，短促） | `Yep.`（语气词，非中文） | 1~2s |

前两条证明**录音设备与识别链路都正常**，用户当时说的就是"喂喂喂"这类试探语。

## 三、修复内容

### 3.1 `app/services/llm_client.py` —— 重排识别链路

```
┌ 1. 魔搭（仅 ASR_PROVIDER=modelscope 时尝试，当前网关不支持，保留以备将来）
├ 2. qwen3-asr-flash（默认主链路）：多模态接口 + data:audio/xxx;base64 直传
└ 3. paraformer 文件转写（兜底，需公网 URL）
```

- 新增 `audio_format(path)`：按**文件头魔数**判断 wav/webm/mp4/m4a/ogg/mp3/flac/amr，不看扩展名
- 新增 `_transcribe_qwen_asr()`：`data:audio/{fmt};base64,<...>` + `asr_options.enable_lid/enable_itn`
- 三级全部失败时，把**每一层的原因串成一条错误**抛出（不再只有"任务失败"）
- TTS 超时 60s → **12s**（实测正常 1.1~1.6s；曾遇一次 >60s 无响应会把整轮交互卡死，失败时前端自动降级浏览器播报）

### 3.2 配置

| 项 | 旧 | 新 |
|---|---|---|
| `ASR_PROVIDER` | modelscope | **dashscope** |
| `TTS_PROVIDER` | modelscope | **dashscope** |
| `LLM_ASR_MODEL` | paraformer-realtime-v2 | **qwen3-asr-flash** |
| `LLM_ASR_MODEL_PARA` | — | **paraformer-v2**（兜底专用） |
| `ASR_MULTIMODAL_API_URL` | — | 新增，多模态接口地址 |

`.env` 与 `.env.example` 同步，并在 `.env.example` 写入了完整排查手册注释（含 404 / SERVER_ERROR 两种典型症状）。

### 3.3 `agent_front/src/views/ElderlyMode.vue`

上传文件名改为按 `blob.type` 推导（mp4→`.m4a`、ogg、wav、mpeg…），不再一律叫 `recording.webm`，避免落盘文件与内容不一致误导排查。

## 五、遗留与建议

1. **paraformer 未开通**：如需更高精度/长音频，可在百炼控制台开通 `paraformer-v2`，届时链路会自动从 qwen 降级到它（当前会自动跳过）。
2. **ngrok 隧道已失效**：`PUBLIC_BASE_URL` 已不再是语音识别的前置条件，但**图像编辑（视角外推）**仍依赖它，需要重新起隧道或改用内网穿透。
3. **魔搭音频能力**：`ASR_PROVIDER/TTS_PROVIDER` 默认已切到 dashscope；若魔搭后续上线音频端点，改回 `modelscope` 即可，代码分支仍在。
4. **"喂喂喂"被识别为 `call_help` 意图**：属 LLM 意图分类的边界情况（语气词被判为求助），如需要可在 `elderly_service` 里加一条"纯语气词 → unknown"的规则。
